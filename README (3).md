## What this project does

Trains one CIFAR-10 CNN (`CarbonNet`) in five variants and measures **energy (kWh)** and **CO₂ (kg)** with [CodeCarbon](https://github.com/mlco2/codecarbon):

| # | Variant | Idea |
|---|---------|------|
| 1 | `baseline_fp32` | normal FP32 training |
| 2 | `mixed_precision` | automatic mixed precision (FP16 on GPU) |
| 3 | `pruned` | baseline → 50 % global L1 pruning → fine-tune |
| 4 | `quantized` | baseline → post-training dynamic INT8 |
| 5 | `pruned_quantized` | pruned model → INT8 |

It also benchmarks CPU inference (energy, latency, size), runs a **carbon-aware scheduler** that shifts a flexible job to low-carbon hours, and exports every table/figure/number used by the IEEE-format report.
Compressed variants are charged for the baseline training they depend on (honest accounting).

## Quick start (Google Colab – recommended)

1. Open `Carbon_Aware_AI_Colab.ipynb` in Google Colab (File → Upload notebook, or open from GitHub).
2. `Runtime → Change runtime type → T4 GPU`.
3. `Runtime → Run all` (≈ 15–20 min on a T4). A `FORCE_QUICK = True` flag in the setup cell gives a ~3 min smoke test.
4. The last cell downloads `carbon_aware_ai_outputs.zip` containing `report_assets/` and `results/`.

## Building the report

1. Run the notebook and unzip `carbon_aware_ai_outputs.zip`.
2. Put `report.tex`, `IEEEtran.cls` and the `report_assets/` folder in the same directory (e.g. an Overleaf project).
3. Compile with pdfLaTeX. All numbers (`numbers.tex`), the results table and figures are filled in automatically; missing files show `XX` or a placeholder box instead of breaking the build.

## Limitations

* CodeCarbon **estimates** CPU/RAM power (TDP-based) in Colab; values are not wall-socket measurements.
* One run per configuration (single seed); small accuracy differences are within noise.
* Dynamic INT8 quantization affects only `nn.Linear`; unstructured pruning does not speed up dense inference.
* The default scheduler data is synthetic – use real Electricity Maps data for final numbers.
